# 5. 이웃 수와 모델 복잡도

KNN에서는 이웃 수 k로 주변 데이터를 얼마나 넓게 참고할지 정함. k는 데이터에서 학습한 무게가 아니라 사람이 지정하는 설정이므로 하이퍼파라미터라고 함. 사이킷런에서는 `n_neighbors`로 전달함.

## 이웃 수와 복잡도의 관계

k가 작으면 소수의 가까운 농어가 예측을 크게 좌우함. 입력 길이가 조금 달라져 이웃이 바뀌면 무게도 민감하게 바뀔 수 있음. 더 세밀한 관계를 표현하는 방향이지만 개별 사례에 지나치게 맞춰질 위험도 커짐.

k가 크면 더 넓은 길이 범위의 무게를 평균함. 개별 농어 한 마리의 영향이 작아져 예측 변화가 완만해지지만 가까운 주변의 중요한 차이까지 평균에 묻힐 수 있음.

따라서 과대적합이 의심되면 k를 늘려 단순하게, 과소적합이 의심되면 k를 줄여 세밀하게 만드는 방법을 시도함. 이 방향으로 조절하면 반드시 성능이 좋아진다는 뜻은 아니며 평가로 확인해야 함.

## 이웃을 다섯 마리에서 세 마리로 줄이기

```python
knr.n_neighbors = 3
knr.fit(train_input, train_target)
print(round(knr.score(train_input, train_target), 4))
print(round(knr.score(test_input, test_target), 4))
```

```text
0.9805
0.9746
```

앞에서 만든 `knr`의 설정을 3으로 바꾸고 같은 훈련 데이터로 다시 준비함. 입력과 정답, 테스트 세트는 그대로이므로 이웃 수 변화의 영향을 비교할 수 있음.

| 이웃 수 | 훈련 R² | 테스트 R² |
| --- | --- | --- |
| 5 | 0.9699 | 0.9928 |
| 3 | 0.9805 | 0.9746 |

훈련 점수는 올라갔지만 테스트 점수는 내려갔음. 소수 이웃의 특징을 더 반영해 훈련 데이터를 잘 맞췄어도 새로운 데이터에 대한 개선이 함께 일어난 것은 아님.

## 복잡도 증가와 성능 개선 구분하기

이 결과에서 확인한 것은 모델을 더 세밀하게 만들자 두 점수가 서로 다른 방향으로 움직였다는 사실임. 원래 모델이 과소적합이었다거나 k=3에서 그 문제가 해결됐다고 단정할 근거는 아님.

목표는 훈련을 가장 잘 맞히는 k를 고르는 것이 아니라 새로운 데이터에서도 잘 예측하는 설정을 찾는 것임. 다음에는 두 후보를 넘어 여러 k에서 R²와 MAE를 함께 비교함. 설정을 선택할 때는 검증 데이터나 교차 검증을 사용하고 테스트는 최종 평가에 남기는 원칙으로 연결됨.
