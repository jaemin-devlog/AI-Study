# 6. 이웃 수별 평가 비교

이웃 수를 5에서 3으로 바꿨을 때 훈련 점수는 올랐지만 테스트 점수는 내려갔음. 이번에는 여러 값을 같은 데이터에서 비교해 변화가 항상 한 방향으로 일어나는지 확인함.

## 바꾸는 조건을 k 하나로 맞추기

```python
for k in [1, 3, 5, 10, 20, 42]:
    model = KNeighborsRegressor(n_neighbors=k)
    model.fit(train_input, train_target)
    mae = mean_absolute_error(test_target, model.predict(test_input))
    print(k, round(model.score(train_input, train_target), 4),
          round(model.score(test_input, test_target), 4), round(mae, 2))
```

```text
1 0.9853 0.9913 22.69
3 0.9805 0.9746 35.42
5 0.9699 0.9928 19.16
10 0.9616 0.9738 39.24
20 0.8613 0.8785 76.44
42 0.0 -0.0551 291.16
```

반복마다 새 회귀 모델을 만들고 같은 `train_input`, `train_target`으로 학습함. 출력은 k, 훈련 R², 테스트 R², 테스트 MAE(g) 순서. `mean_absolute_error()`는 테스트 정답과 그 모델의 예측값을 비교함.

이렇게 데이터 분할과 평가 기준을 유지해야 결과 차이를 k와 연결해 읽기 쉬움. 훈련 R²가 높을수록 훈련에 더 잘 맞고 테스트 R²는 높을수록, 테스트 MAE는 낮을수록 이 테스트에서 좋은 결과임.

## k=1인데 훈련을 모두 맞히지 못하는 이유

이웃 하나라면 자신을 찾아 정답을 그대로 반환할 것 같지만 훈련 R²는 약 0.9853임. 같은 길이인데 무게가 다른 농어가 있어 거리 0인 이웃이 여러 개일 수 있기 때문임. 입력은 길이 하나라 이들을 구별할 정보가 없음.

동률인 이웃 중 다른 농어의 무게를 사용하면 실제 무게와 차이가 생김. 동률 처리에 따라 일부 수치가 달라질 수 있으므로 k=1이면 언제나 훈련 점수가 1이라고 외우지 않음.

## k=42에서 모든 예측이 같아지는 이유

42는 훈련 농어 전체 수. 어느 길이가 들어오든 모든 농어를 이웃으로 고르므로 예측은 훈련 무게의 평균 하나가 됨. 길이에 따른 증가 관계를 반영하지 못하는 상태임.

훈련에서는 평균 예측 기준과 모델이 같아 R²가 0임. 테스트에서는 모델이 훈련 평균을 반환하지만 R²의 기준은 테스트 정답 평균임. 두 평균이 달라 테스트 R²는 약 -0.0551이 됨. 음수는 평균 기준보다 제곱오차가 더 크다는 뜻임.

## 한 표에서 비교할 수 있는 것

k=20과 42에서는 훈련과 테스트 성능이 모두 낮아지고 MAE도 커짐. 반면 작은 k끼리의 테스트 점수는 일정하게 증가하거나 감소하지 않음. 이 후보에서는 k=5가 테스트 R² 약 0.9928로 가장 높고 MAE 약 19.16g으로 가장 낮음.

이 결과는 이번 분할에서의 관찰이며 모든 데이터에서 이웃 다섯 개가 최적이라는 뜻은 아님. k를 실제로 고를 때는 검증 성능으로 비교함. 다음 파일에서는 같은 차이가 예측선에 어떻게 나타나는지 살펴봄.
