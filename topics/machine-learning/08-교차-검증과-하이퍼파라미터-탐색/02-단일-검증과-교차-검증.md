# 2. 단일 검증과 교차 검증

앞에서 전체 와인 중 테스트를 남기고 훈련용 4,157개와 검증용 1,040개를 나눴음. `sub_input`, `sub_target`은 모델을 학습할 데이터이고 `val_input`, `val_target`은 그 모델을 확인할 데이터임.

## 한 번 나눈 검증 세트로 평가하기

```python
from sklearn.tree import DecisionTreeClassifier

dt = DecisionTreeClassifier(random_state=42)
dt.fit(sub_input, sub_target)
print(round(dt.score(sub_input, sub_target), 4))
print(round(dt.score(val_input, val_target), 4))
```

```text
0.9971
0.8644
```

| 평가 데이터 | 정확도 | 의미 |
| --- | ---: | --- |
| 훈련 | 0.9971 | 학습에 사용한 와인을 약 99.71% 맞힘 |
| 검증 | 0.8644 | 학습하지 않은 와인을 약 86.44% 맞힘 |

깊이를 제한하지 않은 트리가 훈련 와인에서는 약 99.71%를 맞혔지만, 학습에 사용하지 않은 검증 와인에서는 약 86.44%를 맞힘. 훈련에 비해 검증 성능이 낮아 훈련 사례에 지나치게 맞춰진 과대적합을 의심할 수 있음. 모델의 복잡도를 조절한다면 테스트가 아니라 이 검증 결과를 비교 기준으로 삼아야 함.

## 한 번의 분할만으로 판단할 때

검증용을 크게 떼어 두면 점수를 계산할 샘플은 많아지지만 실제로 모델을 학습할 데이터가 줄어듦. 반대로 검증용이 너무 작으면 어떤 와인이 선택됐는지에 따라 점수가 크게 달라질 수 있음.

또 한 번 정한 1,040개로만 평가하면 그 분할에서 우연히 쉬운 샘플이나 어려운 샘플이 많이 들어간 영향을 받을 수 있음. 이런 영향을 줄이기 위해 훈련과 검증의 구성을 바꿔 여러 번 평가하는 방법이 교차 검증임.

## 폴드를 번갈아 검증에 사용하기

테스트 1,300개를 그대로 남겨 둔 채, `train_input` 5,197개를 다섯 부분으로 나눔. 이 한 부분을 폴드라고 함. 한 회차에서는 네 폴드로 학습하고 나머지 한 폴드로 검증함. 검증 폴드를 바꾸어 다섯 번 반복함.

![5폴드 교차 검증](../assets/pdf/5폴드-교차-검증.png)

그림의 각 행은 한 회차. 보라색 폴드는 그 회차의 검증용이고 나머지 파란 폴드는 학습용임. 각 와인은 전체 다섯 회차에서 한 번 검증에, 네 번 학습에 사용됨. 다섯 점수의 평균으로 한 설정을 평가함.

각 회차에서는 같은 설정의 모델을 새로 학습함. 첫 번째 모델을 계속 이어서 학습하며 다른 폴드에 적용하는 방식이 아님. 매 회차에서 그 회차의 검증 폴드는 모델 학습에 들어가지 않음.

## 점수의 평균이 의미하는 것

교차 검증은 서로 다른 분할에서 해당 설정이 어떤 결과를 내는지 확인하는 평가 방법임. 점수를 평균한다고 모델의 예측을 합치는 앙상블이 되거나, 학습된 모델이 자동으로 더 좋아지는 것은 아님.

한 설정을 선택한 뒤에는 그 설정으로 테스트를 제외한 전체 훈련 데이터를 다시 학습할 수 있음. 처음 남긴 테스트 1,300개는 어떤 회차의 검증 폴드에도 넣지 않음. 다음 파일에서는 이 과정을 `cross_validate()`로 실행함.
