# 텍스트 분류에서 요약까지

> Day 5 종합 정리, 1~7절 (1~12쪽). 특히 사전학습 모델과 요약은 6절 (9~12쪽).

## 모델이 필요한 이유를 연결하기

| 모델 또는 방법 | 해결하려는 문제 | 핵심 방법 |
| --- | --- | --- |
| RNN | 순서와 앞의 정보를 함께 사용 | 은닉 상태를 다음 시점으로 전달 |
| LSTM·GRU | 오래전 정보의 유지와 학습 | 게이트로 정보 흐름 조절 |
| Attention | 현재 예측에 맞는 입력 참고 | 여러 입력 표현에 가중치 부여 |
| Transformer | 순환 없이 토큰 관계 계산 | Self-Attention과 위치 정보 사용 |

앞 모델을 무조건 버려야 하는 순위표가 아님. 입력 길이, 필요한 출력, 데이터 크기, 계산 자원에 맞춰 구조를 선택함.

## 분류와 생성은 출력이 다름

IMDB 분류는 리뷰 전체를 보고 긍정일 확률을 계산함. 요약은 원문을 보고 새로운 토큰 시퀀스를 생성함. 두 작업 모두 숫자 표현을 사용하지만 정답의 형태와 평가 방법이 다름.

| 구조 | 강의의 대표 예 | 활용 |
| --- | --- | --- |
| Encoder-only | BERT | 입력 표현과 분류 |
| Decoder-only | GPT | 다음 토큰 생성 |
| Encoder–Decoder | BART, T5 | 입력을 참고한 번역과 요약 |

종합 정리에는 영어 DistilBART와 한국어 KoBART 요약 실습이 소개됨. 요약용으로 미세 조정된 모델을 불러와 추론하는 과정이며, 이 노트에서 직접 모델을 실행하거나 정확도를 측정한 것은 아님.

## 사전학습, 미세 조정, 추론

사전학습은 큰 데이터로 일반적인 패턴을 배우는 과정임. 미세 조정은 특정 작업 데이터로 가중치를 추가 학습하는 과정이고, 추론은 학습된 가중치를 이용해 결과를 계산하는 과정임. 모델을 불러와 요약문을 생성하는 것만으로 가중치가 새로 학습되지는 않음.

## Tokenizer의 역할

Tokenizer는 모델이 학습한 어휘 체계에 맞춰 텍스트를 토큰 ID로 바꿈. 단어 전체 대신 더 작은 Subword 단위가 사용될 수 있음. 모델과 맞는 Tokenizer를 사용해야 같은 ID가 같은 의미의 토큰을 가리킴.

```text
원문 → Tokenizer → ID → Embedding → Encoder
                                      ↓
요약문 ← decode ← 생성 ID ← Decoder가 입력을 참고해 생성
```

`tokenize()`는 토큰 분리, `convert_tokens_to_ids()`는 ID 변환, `encode()`는 텍스트의 ID 인코딩, `decode()`는 생성 ID의 문자열 복원을 담당함.

## 결과를 설명할 때 확인할 것

분류는 검증 손실로 모델을 고르고 별도 테스트 데이터의 정확도 등을 확인함. 요약은 문장의 자연스러움과 함께 원문의 핵심 정보 유지, 사실 일치, 반복 여부를 확인함. 자연스러운 문장이어도 원문에 없는 내용을 만들 수 있으므로 원문과 비교해야 함.

복습할 때는 “RNN의 상태는 원문을 완벽히 보관하는가?”, “ID와 임베딩은 어떻게 다른가?”, “LSTM만 추가로 반환하는 상태는 무엇인가?”, “Q·K로 계산한 가중치를 어디에 적용하는가?”, “Encoder와 Decoder는 각각 무엇을 출력하는가?”를 자신의 말로 설명해 봄.
