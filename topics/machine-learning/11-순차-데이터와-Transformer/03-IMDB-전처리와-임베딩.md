# IMDB 전처리와 임베딩

> Day 5 이론 2, 2~4절 (2~12쪽)

## 리뷰를 숫자로 표현하기

IMDB는 영화 리뷰를 긍정 1과 부정 0으로 분류하는 문제임. 강의 데이터는 훈련용과 테스트용이 각각 25,000개이며, 훈련용에서 일부를 검증용으로 분리함.

토큰화는 문장을 처리할 단위로 나누는 작업이고, 정수 인코딩은 각 토큰에 ID를 부여하는 작업임. 같은 단어에 같은 ID를 사용하지만, ID 자체가 문장을 구분하는 번호는 아님. 문장은 여러 ID의 순서로 표현됨.

## 어휘 500개와 OOV

강의는 빈도 기반 단어 인덱스에 시작 토큰 등을 반영한 뒤 ID를 500 미만으로 제한함. 사람이 임의로 단어 500개를 직접 적어 두는 방식은 아님. 특별한 ID도 사용하므로 일반 단어가 정확히 500개라는 뜻은 아님.

| ID | 역할 |
| --- | --- |
| 0 | 길이를 맞추는 Padding |
| 1 | 리뷰 시작 |
| 2 | 어휘 범위 밖의 토큰 OOV |
| 범위 안의 단어 ID | 해당 단어 구분 |

범위 밖 단어도 문장에서 무조건 삭제하지 않고 2로 대체함. 서로 다른 희귀 단어가 같은 2가 되므로 그 단어들 사이의 구체적인 구별은 사라짐.

## 길이 100으로 맞추기

강의는 긴 리뷰의 마지막 100개 토큰을 남기고 짧은 리뷰는 앞쪽에 0을 채움. 같은 배치의 리뷰를 직사각형 텐서로 묶기 위한 처리임. 긴 리뷰를 자르면 앞부분의 정보가 없어질 수 있으므로 길이 선택에도 손실이 있음.

```text
설명용 길이 5
[1, 7, 9]          → [0, 0, 1, 7, 9]
[1, 4, 6, 8, 9, 7] → [4, 6, 8, 9, 7]
```

## ID를 벡터로 바꾸기

ID 100이 ID 10보다 열 배 중요한 단어는 아님. 원-핫 인코딩은 해당 ID 위치만 1로 표시해 번호의 크기를 수치 특성으로 취급하지 않게 함. 어휘가 많으면 벡터도 길어짐.

`nn.Embedding(500, 16)`은 500행, 16열의 학습 가능한 표임. ID에 해당하는 행을 꺼내 토큰을 16개 실수로 표현함. 임베딩은 리뷰 분류 손실의 역전파를 통해 함께 학습됨. 각 차원이 사람이 정한 “긍정 정도” 같은 뜻을 반드시 갖는 것은 아님.

강의의 Embedding에는 `padding_idx`가 지정되지 않았으므로 ID 0도 자동으로 무시되지 않음. `padding_idx=0`을 사용하더라도 RNN의 패딩 타임스텝 자체가 생략되는 것은 아니라는 점을 구분함.
