# 6. 추가 학습과 파라미터 변화

앞에서는 추가 학습 전후 정확도를 봤음. 이번에는 모델 안의 계수와 절편도 비교함. 같은 입력에 다른 파라미터를 적용하면 점수와 확률이 바뀔 수 있지만 최종 이름까지 반드시 바뀌는 것은 아님.

앞 파일의 `SGDClassifier`, `train_scaled`, `test_scaled`와 각 정답을 사용함. `np`는 NumPy를 가리킴.

## 추가 학습 전 상태 보관하기

모델을 새로 학습한 뒤 `.copy()`로 계수와 절편을 복사함. 갱신 뒤에도 이전 숫자를 독립적으로 보관해야 전후를 비교할 수 있기 때문임. 평가 데이터는 바꾸지 않고 추가 학습만 한 번 진행함.

```python
sc_compare = SGDClassifier(loss='log_loss', max_iter=10, random_state=42)
sc_compare.fit(train_scaled, train_target)
coef_before = sc_compare.coef_.copy()
intercept_before = sc_compare.intercept_.copy()
before = [sc_compare.score(train_scaled, train_target),
          sc_compare.score(test_scaled, test_target)]
sc_compare.partial_fit(train_scaled, train_target)
after = [sc_compare.score(train_scaled, train_target),
         sc_compare.score(test_scaled, test_target)]
print(not np.allclose(coef_before, sc_compare.coef_))
print(not np.allclose(intercept_before, sc_compare.intercept_))
print(np.round(before, 4))
print(np.round(after, 4))
```

```text
True
True
[0.7815 0.8   ]
[0.8067 0.825 ]
```

`np.allclose()`는 전후 배열이 허용 오차 안에서 같은지 확인함. 앞에 `not`을 붙였으므로 첫 `True`는 계수가 달라졌고 둘째는 절편이 달라졌다는 뜻임.

`before`와 `after`는 훈련, 테스트 정확도 순서. 두 점수도 상승했으므로 이번 실행에서는 파라미터 갱신과 예측 결과의 개선을 함께 확인할 수 있음.

| 평가 항목 | 추가 학습 전 | 추가 학습 후 |
| --- | ---: | ---: |
| 훈련 정확도 | 0.7815 | 0.8067 |
| 테스트 정확도 | 0.8000 | 0.8250 |

같은 `sc_compare` 모델을 한 번 더 학습한 결과를 나란히 놓은 것임. 추가 학습이 항상 두 점수를 높여 준다는 뜻은 아님.

## 파라미터가 달라도 정확도는 같을 수 있음

확률 0.6과 0.9가 모두 같은 양성 이름으로 선택됐던 것처럼, 파라미터가 바뀌어도 기존 이름이 그대로 선택될 수 있음. 일부 이름이 바뀌더라도 맞게 바뀐 개수와 틀리게 바뀐 개수가 같으면 전체 정확도는 그대로일 수 있음.

따라서 파라미터 비교는 모델 내부가 수정됐는지 확인하는 방법이고 정확도 비교는 맞힌 비율을 확인하는 방법임. 정확도가 그대로라는 사실만으로 학습이 진행되지 않았다고 판단할 수 없음.

## 추가 학습을 언제까지 할까?

반복이 부족하면 훈련 데이터의 관계를 충분히 반영하지 못하고, 너무 오래 학습하면 훈련 사례에만 맞춰질 수 있음. 훈련 정확도만 계속 관찰하면 어느 시점에서 멈출지 판단하기 어려움. 다음 파일에서는 검증 데이터를 따로 두고 여러 에포크의 변화를 기록함.
