# Git과 GitHub

프로젝트를 수정할 때마다 `final.py`, `final2.py`처럼 파일을 복사하면 어느 파일이 최신인지, 어떤 이유로 바뀌었는지 확인하기 어려워짐. 여러 파일을 함께 수정했다면 특정 시점에 어떤 조합이 정상적으로 동작했는지도 찾기 어려움. Git은 프로젝트의 변경 상태를 버전으로 기록하고 이전 상태와 비교할 수 있게 해 줌.

## 버전이란 무엇일까?

버전은 특정 시점의 프로젝트 상태를 구분하는 기준. 하나의 버전에는 코드 한 파일만이 아니라 그 시점에 Git이 관리한 여러 파일의 상태가 함께 담김. 새 버전을 만들더라도 이전 버전은 덮어쓰지 않고 이력으로 남음.

예를 들어 모델 설정과 평가 결과를 함께 수정했다면 두 파일을 하나의 커밋으로 기록할 수 있음. 이후 설정이 잘못되었을 때 어느 버전에서 무엇이 달라졌는지 비교하고, 기록된 이전 상태를 확인할 수 있음. Git이 코드의 성능을 자동으로 판단하는 것은 아니므로 실험 목적과 결과는 사람이 정리해야 함.

Git에서 기록한 한 버전을 커밋(Commit)이라고 함. 커밋에는 파일 상태와 메시지, 작성자, 이전 커밋과의 관계가 저장됨. 커밋 해시는 각 커밋을 식별하는 값이고 메시지는 그 기록이 어떤 작업인지 설명함.

## Git, GitHub, VS Code의 역할

| 도구 | 역할 |
| --- | --- |
| Git | 내 컴퓨터의 저장소에서 버전과 브랜치를 관리 |
| GitHub | Git 저장소를 원격으로 보관하고 공유와 리뷰를 지원 |
| VS Code 소스 제어, SourceTree | Git 작업을 버튼과 화면으로 다룰 수 있는 도구 |

Git은 GitHub 계정이 없어도 로컬에서 사용할 수 있음. VS Code나 SourceTree에서 커밋 버튼을 눌러도 이력을 실제로 관리하는 것은 Git임. 터미널 명령어와 화면 조작은 같은 Git 상태를 서로 다른 방식으로 다룸.

로컬 저장소는 내 컴퓨터에 있고, 원격 저장소는 GitHub 같은 서버에 있음. 로컬 커밋은 자동으로 원격에 올라가지 않음. 로컬에만 있으면 컴퓨터의 파일을 잃었을 때 이력도 함께 잃을 수 있으므로 원격 보관 여부를 따로 확인해야 함.

## 파일 저장부터 원격 공유까지

| 단계 | 달라지는 것 |
| --- | --- |
| 파일 저장 | 편집한 내용이 내 작업 폴더의 파일에 반영됨 |
| `git add` | 현재 파일 상태가 다음 커밋을 위한 스테이지에 준비됨 |
| `git commit` | 준비한 상태가 로컬 이력에 하나의 버전으로 기록됨 |
| `git push` | 로컬 커밋이 연결된 원격 저장소에 전송됨 |

파일을 저장하는 것만으로 커밋이 생기지 않음. 커밋을 만들어도 GitHub에 자동으로 올라가지 않음. 각 단계는 서로 다른 위치의 상태를 바꾸기 때문에 현재 어느 단계까지 진행했는지 확인해야 함.
